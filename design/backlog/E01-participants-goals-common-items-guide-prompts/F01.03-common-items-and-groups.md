# F01.03 Common items and groups

**Outcome:** managers keep the organisation's common items in groups on one screen: the built-in Every note group is
always first and cannot be renamed, moved or archived; other groups are added, renamed, reordered, archived and
restored; items are added, reworded, reordered, moved to another group, archived and restored (D44, D45, A41–A43).
Nothing is deleted.

## Stories
- S01.03.01 Every note group, built in
- S01.03.02 Add and reword common items
- S01.03.03 Reorder common items in a group
- S01.03.04 Archive and restore common items
- S01.03.05 Add and rename groups
- S01.03.06 Reorder groups
- S01.03.07 Archive and restore groups
- S01.03.08 Move a common item to another group

## Feature checks
Owns these rows in [coverage.md](../coverage.md):
- design.md §14 M1 *Scope*, "the organisation-wide common items in their groups (groups: add, rename, reorder,
  archive, restore; items: add, reword, reorder, move to another group, archive, restore; the built-in Every note group
  created with the organisation, D44, D45)".
- design.md §14 M1 *Done when*, "The Every note group cannot be renamed, moved or archived, and a second one cannot be
  created (API and database tests)." The database tests are in S01.03.01; the API tests in S01.03.05, S01.03.06 and
  S01.03.07.
- `common-items.md › Content and copy`, `› Layout`, `› Loading, empty, errors`, `› Reordering`, `› Add, edit, rename,
  move`, `› Archive and restore`, `› Failures and conflicts`.

`common-items.md › Accessibility runs` is a Definition of Done row.

As a manager, I want the Every note group to be there from the start, always first and fixed, so that its items
show on every note and nobody can rename, move or archive it by mistake.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §14 M1](../../design.md#m1-participants-goals-common-items-and-groups-guide-prompts) *Done when*, the
  Every note line (database part).
- design.md §5.3 CommonItemGroup *Constraints* and CommonItem; §4.9 items 1 and 2; A43.
- [common-items.md](../../ux/screens/common-items.md) › Acceptance criteria › Content and copy, every bullet (the
  group sections fill in as S01.03.02 and S01.03.05 add rows), and › Loading, empty, errors, every bullet.

Specific to this story:
- [ ] The `CommonItemGroup` and `CommonItem` tables with the filtered unique index (one Every note per organisation)
      and the check constraint (Every note never archived), and `DENY DELETE` for `grow2notes_runtime`.
- [ ] Database tests: a second Every note row for an organisation fails; archiving Every note fails.
- [ ] `admin bootstrap` creates the Every note group in the same transaction as the organisation (design.md §7.4).
- [ ] A migration gives every organisation that already exists, such as the one bootstrapped in test during E00,
      exactly one Every note group.
- [ ] `GET /api/admin/common-item-groups?includeArchived=` returns Every note first, then the other groups in order,
      each with its items, and a `rowVersion` on every group and item.
- [ ] No endpoint creates a group with `IsEveryNote = 1`.

### Notes
- The assumed defaults A41–A47 and the 200-character group name (A6) are open for the owner to confirm
  ([ux/README.md](../../ux/README.md) open question 11). A41–A43 and A45 apply here; A44 and A46–A47 are E02's.

As a manager, I want to add common items to a group and fix their wording, so that writers can tick them on notes.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- design.md §4.9 item 4 (the item list, "New item in [group name]", Add item).
- [common-items.md](../../ux/screens/common-items.md) › Acceptance criteria › Add, edit, rename, move, these bullets:

  "A `412` on an item Save…" and "A `401` during any write…".

Specific to this story:
- [ ] `POST /api/admin/common-item-groups/{groupId}/items` adds the item at the end of an active group and writes
      `common_item.created`; for an archived group it returns `409 config.group_archived`.
- [ ] `PUT /api/admin/common-items/{id}` with an unchanged group needs `If-Match` and writes `common_item.updated`
      with the old and new wording; it returns `409 config.group_archived` when the item's group is archived.
- [ ] The server also saves line breaks as single spaces.
