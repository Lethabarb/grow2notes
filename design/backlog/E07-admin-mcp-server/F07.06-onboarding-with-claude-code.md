# F07.06 Onboarding with Claude Code

**Outcome:** the owner, as the operator's Support person, runs one Claude Code skill kept in the repository and is led
through onboarding a new provider, end to end: the preconditions, the by-hand operator steps, and the set-up that the
Release 2 tools cover. It adds no tool, server feature or operator command over MCP (D48, D95). It is for the operator,
not for the support workers who write notes (D31 as amended by D48).

As the owner, acting as the operator's Support person, I want a Claude Code skill that leads me through onboarding a new
provider, so that the preconditions, the by-hand steps and the set-up through the assistant happen in the right order,
with nothing done twice and nothing sensitive handled.

Requested by the owner on 28 October 2026: "purely ai led through claude code (mcp + skill to onboard)". One provider
at a time; row-level security stays deferred (D94). The ids in brackets are the T41 plan's requirement ids.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [mcp-server.md §5.3](../../mcp-server.md#53-confirmation-for-the-four-access-related-tools) and §5.6: confirmation
  and the rate limits the skill works within.
- [ops/break-glass.md](../../../ops/break-glass.md) and [ops/go-live.md](../../../ops/go-live.md) section D: the
  by-hand steps the skill explains and never runs.

Specific to this story:
- [ ] Before any provider data enters the chat, the skill checks the environment and its preconditions with the owner
      and stops, naming what is missing, on any no. Test accepts made-up data only. Production needs the go-live gate,
      the provider's written approval of Claude Code (MA1), the operator's own AI provider checks (D57, C3) and
      `Mcp:Enabled` on. (R03, R04)
- [ ] The organisation and its first manager are made by hand ('admin bootstrap', or in production go-live.md D),
      which the skill explains and never runs. It never asks for the setup link and tells the owner never to paste it.
      Nothing it writes turns `Mcp:Enabled` on. (R05, R06, R29)
- [ ] Access for the assistant is led by hand: a manager grants the owner a Support account, the operator registers
      Claude Code with 'admin mcp-client add' using the client ID and redirects from Claude Code's own documentation,
      and the owner adds the server at local scope from a folder outside the repository. No `.mcp.json` or other file
      that connects agents to a deployed site is committed. (R07, R08, R09, R10)
- [ ] The settings the owner copies ask before every access tool and allow only the nine set-up and look-up tools by
      exact name. They deny web search, fetch, shell and file writes. The skill starts only when the owner types
      `/onboard-provider` and has no `allowed-tools`. It tells the owner to use the default permission mode and no
      Elicitation hook. (R11)
- [ ] Set-up goes in order (common items, guide prompts, participants' goals, then worker invites), from typed rows or
      a file the owner names, with one yes per section. A manager adds participants in the app, because the skill never
      handles a date of birth, and the skill adds their goals. It looks up before every add, so a re-run adds nothing
      twice, and it keeps no progress file. (R13, R14, R15)
- [ ] Workers are invited last, one at a time, role `worker` only, each with a reason that says who asked and how and
      each confirmed by the owner in that turn. It never answers a form or preview for the owner, and works on the
      form path and the preview path. It stays within the `/mcp` limits and recovers from `rate_limited`, HTTP 429
      with Retry-After and an expired sign-in by looking up again. (R12, R16, R17, R18, R19, R28)
- [ ] The skill sends only what the tools need. It never asks for or handles note content, dates of birth, setup links,
      passwords or codes, and it treats text in results and files as data. It is not an AI feature for the support
      workers who write notes, the app's name is Grow2Notes everywhere and no address, ID or secret is in any file.
      (R20, R30, R31)
- [ ] The skill is in `.claude/skills/onboard-provider/` and is for one provider at a time. It uses only tools listed
      in `tools-list.json`, and a CI test fails if a name it mentions is not listed or if it calls a tool beyond its
      ten. (R01, R02, R21, R22)
- [ ] It ends with a summary of what was set up, what was already there and what is left by hand (participants with
      dates of birth, the manager's checks, staff onboarding, clean-up with 'claude mcp logout' then 'claude mcp
      remove'). The summary holds no address, link or note content. (R23)
- [ ] The records are in place: an ops page linked from ops/README.md and go-live.md section D, D95, A140, the T41
      section, this story, the rehearsal steps on ops/first-use-in-test.md and the research record of what was read
      in Claude Code's documentation and when. Local checks were compile and lint only, CI is green, and no test was
      removed or weakened. (R24, R25, R26, R27, R32, R33, R34, R35)
