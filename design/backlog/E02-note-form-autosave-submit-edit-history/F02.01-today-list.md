# F02.01 Today list

**Outcome:** everyone lands on Today and sees every active participant under today's Melbourne date, with the
status of today's note where one exists, a way to find a participant by name, and their own unfinished drafts and
pending edits that are not on today's list ([design.md §4.2](../../design.md#42-today-home-for-everyone), A17).

## Stories
- S02.01.01 See every active participant on Today
- S02.01.02 Find a participant
- S02.01.03 See today's note status on each row
- S02.01.04 Continue an unfinished draft from Today

## Feature checks
This feature owns these rows in [coverage.md](../coverage.md) (E02):

- design.md §14 M2 *Scope*: "The Today list (all participants, D20), 'Your unfinished drafts', and participant
  history." The participant history part is delivered by S02.04.02 (F02.04); check the row once that story is done.
- [today.md › Acceptance criteria](../../ux/screens/today.md#acceptance-criteria): Content and copy; Order and
  layout; Loading, empty and error; Search; Focus and navigation; Refresh; Automated and manual checks.
- today.md › Privacy (D22, §9.6) is marked DoD and is checked on every story.

Spans its stories:

- today.md › Focus and navigation, bullet "After Submit: the banner is before the `<h1>`…", is delivered by S02.03.01.
- today.md › Automated and manual checks: run axe on every Today state once all four stories are done, and do the
  NVDA, VoiceOver and TalkBack pass then.

As a worker, I want Today to list every active participant under today's date,
so that I can open the person I am supporting from one place.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.2](../../design.md#42-today-home-for-everyone): items 1 and 4, and the state "No participants".
- [design.md §6.3](../../design.md#63-today-participants-and-notes): `GET /api/today`.
- [today.md › Acceptance criteria](../../ux/screens/today.md#acceptance-criteria) › Content and copy: "Title is…",
  "`<h1>` reads…", "Nowhere on the screen…", "Long names…".
- today.md › Order and layout: every bullet except "Drafts section lists only…" (S02.01.04).
- today.md › Loading, empty and error: every bullet except "The drafts section and list appear…" (S02.01.04) and
  "The search box is not in the DOM…" (S02.01.02).
- today.md › Focus and navigation: "Back (or '‹ Today', which pops)…", "Arriving by the nav or wordmark…", "Row links
  carry only IDs and dates…".
- today.md › Refresh: both bullets, for the Today query (the drafts query joins in S02.01.04).

Specific to this story:
- [ ] `GET /api/today` returns only the caller's organisation's active participants, sorted by family name then
      given name (A5); an archived participant is not listed (§3.7). Its `date` comes from `MelbourneClock`
      (S00.01.01).
- [ ] Endpoint matrix rows: anonymous `401`; worker and manager `200` with the same list; a manager of a second
      organisation sees none of these participants (design.md §2, §5.9).
- [ ] Given the server clock at 2026-10-03T14:30Z and the device clock set to another date and time zone, when Today
      loads, then the heading reads "Today · Sunday 4 October" and every row links to `…/notes/2026-10-04`.
- [ ] A row opens `/participants/{participantId}/notes/{date}` and pushes no router state (note-form.md Routes).

### Notes
- Until S02.01.03, `note` is `null` on every row, so no row has a status line.
- The managers' "Add participant" link in the empty state goes to E01's Add participant page.
- Copy marked (P) on this screen (today.md Open question 1) ships with the proposed wording unless the owner
  changes it.
- Owner answer, 9 October 2026: every (P) string in the UX specs on that date is approved as written (D67), so the (P)
  copy above ships as written; it can still be changed later in the copy module. This answers today.md Open question 1.

As a worker, I want each row on Today to show whether today's note is a draft or submitted, and who has it,
so that I can see at a glance what has been done today and who is writing which note.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.2](../../design.md#42-today-home-for-everyone): item 4 (the four status forms) and A17.
- [design.md §6.3](../../design.md#63-today-participants-and-notes): the `note` object in `GET /api/today`.
- [today.md › Acceptance criteria](../../ux/screens/today.md#acceptance-criteria) › Content and copy: "Rows show
  exactly the four status forms…", "'Flagged' appears only on Submitted rows…", "Times are Melbourne time…".
- today.md › Focus and navigation: "Opening a row whose cached status is stale…".

Specific to this story:
- [ ] `note` is filled from the live note (Draft or Submitted) dated today; a discarded draft gives `null`
      (§3.4, §5.5).
- [ ] `savedAtUtc` is returned only on the caller's own draft. For someone else's draft the row data holds the
      author's display name and start time only, never draft content (A9).
- [ ] Given Alex P. started Jane Citizen's draft at 9:14 am, when another worker and a manager load Today, then both
      rows read "Draft · Alex P. · started 9:14 am".
- [ ] "Submitted · … · 4:12 pm" uses `firstSubmittedAtUtc`. The Flagged tag follows the current version's
      `isFlagged`, not the review state (checked once S02.03.02 is done).

- today.md Open question 3 (a pending edit on today's submitted note shows nothing on Today) is built as specified
  unless the owner decides otherwise.

As a worker, I want Today to list my drafts and pending edits that are not on today's list,
so that I can finish a note I started on an earlier day or for someone archived since.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.2](../../design.md#42-today-home-for-everyone): item 2, and A17.
- [design.md §6.3](../../design.md#63-today-participants-and-notes): `GET /api/me/drafts`.
- [note-form.md Routes](../../ux/screens/note-form.md#routes): `kind: "draft"` rows push the shared note URL;
  `kind: "pendingEdit"` rows push `/edit`.
- [today.md › Acceptance criteria](../../ux/screens/today.md#acceptance-criteria) › Order and layout: "Drafts section
  lists only drafts/pending edits not on today's list…".
- today.md › Loading, empty and error: "The drafts section and list appear in the same render…".
- today.md › Refresh: the drafts query refetches with the Today query.

Specific to this story:
- [ ] `GET /api/me/drafts` returns only the caller's own working copies (drafts and pending edits) in the caller's
      organisation: never another user's, and never the working copy kept with a discarded draft (§5.3 NoteDraft
      rules).
- [ ] Given a worker's draft dated yesterday (fake clock), when they open Today, then the section lists the
      participant with "Wednesday 30 September 2026" and the row opens that draft.
- [ ] A draft for a participant archived since is listed and opens (§3.7: a draft already started can still be
      submitted).
- [ ] The caller's own draft dated today for an active participant is not in the section.
- [ ] A pending edit row opens `/participants/{participantId}/notes/{noteDate}/edit` (checked once S02.06.01 is
      done).

### Notes
- today.md Open question 2 (should pending edits say "Editing submitted note"?) is built as name and date only, as
  §4.2 says, unless the owner decides otherwise.
