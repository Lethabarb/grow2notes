# F02.08 Past-day notes

**Outcome:** a manager picks a past date for a participant and writes the forgotten note with the same form and
lifecycle as any other note. The manager is its author, and the note shows its note date and when and by whom it was
written everywhere it appears (D35, A11, [design.md §3.8](../../design.md#38-past-day-notes-managers)).

## Stories
- S02.08.01 Choose the date for a past-day note
- S02.08.02 Write and submit a forgotten past-day note

## Feature checks
This feature owns these rows in [coverage.md](../coverage.md) (E02):

- design.md §14 M2 *Scope*: "Past-day notes for managers. Melbourne 'today' through `TimeProvider`." The
  `TimeProvider` clock is built by S00.01.01, and S02.02.01 proves it across daylight saving.
- [participants.md › Acceptance criteria](../../ux/screens/participants.md#acceptance-criteria): Write past-day note.
  The participants screen is E01's; this group is here because past-day notes are M2 scope.

This feature also delivers parts of rows owned elsewhere: note-form.md › Common items and groups item 30e (a
manager's past-day note copies picks from the latest submitted note before its date, F02.05); participant-notes.md ›
Read view item 20 (the past-day line, F02.04); version-history.md › Page A, the `isPastDayNote` bullet (F02.07).

As a manager, I want to write and submit a note for a past date that has none,
so that a forgotten support is on record, with me shown as the author and the date it was written.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §2](../../design.md#2-roles--permissions) ("Write a note for a past date": managers only),
  [§3.8](../../design.md#38-past-day-notes-managers), §4.3 item 2 (the past-day banner), §5.3 `Note.CreatedAtUtc`,
  §5.5 item 4, §5.7 *Starting picks*, and §6.3 `isPastDayNote`.
- [note-form.md States › Kinds of note](../../ux/screens/note-form.md#kinds-of-note-set-when-the-form-loads): "Manager's
  past-day note".
- [note-form.md › Acceptance criteria](../../ux/screens/note-form.md#acceptance-criteria) › Common items and groups:
  item 30e, the past-day sentence.
- [participant-notes.md › Acceptance criteria](../../ux/screens/participant-notes.md#acceptance-criteria) › Read
  view: item 20, the past-day line.
- [version-history.md › Acceptance criteria](../../ux/screens/version-history.md#acceptance-criteria) › Page A: "With
  `isPastDayNote`…".

Specific to this story:
- [ ] Given a manager and a past date with no live note, when the first change is saved, then the note is created for
      that date with the manager as author, and `isPastDayNote` is true (the Melbourne date of `CreatedAtUtc` is after
      the note date).
- [ ] Given a worker, the same request returns `422 note.past_date_manager_only`; given an archived participant,
      `422 note.participant_archived`; nothing is created.
- [ ] The form shows "Past-day note for Monday 28 September 2026, written on Thursday 1 October 2026." and the
      confirmation title reads "Submit the note for".
- [ ] Starting picks come from the most recent submitted note before the note date, not from a later note.
- [ ] The read view and the version pages show "Past-day note, written by {manager} (manager) on {date, time}" in
      place of "Written by"; a worker's draft submitted after midnight never shows it.
