# F02.06 Edit a submitted note

**Outcome:** the author or any manager edits a submitted note through a pending edit that only they see. Save changes
adds exactly one new version, Cancel leaves the note unchanged, everyone sees the Edited label, and nothing is ever
silently overwritten (D15, D19, [design.md §3.5](../../design.md#35-editing-and-versions), §5.8).

## Stories
- S02.06.01 Edit my own submitted note
- S02.06.02 Edit any submitted note as a manager
- S02.06.03 Handle two people editing the same note

## Feature checks
This feature owns these rows in [coverage.md](../coverage.md) (E02):

- design.md §14 M2 *Scope*: "Submit creates version 1; Save changes by the author or a manager creates the next
  version; pending edits and Cancel; version history for managers."
- design.md §14 M2 *Done when*: "Each Save changes adds exactly one version, and earlier versions are byte-for-byte
  unchanged."

Delivered by stories in other features (check these parts when those stories are done):

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §3.5](../../design.md#35-editing-and-versions), §3.9 (a submitted note on the wrong participant is
  corrected by editing it), §4.3 state "Editing a submitted note", and §4.4 (Edit; the "Edited" label).
- [design.md §5.7](../../design.md#57-which-items-a-note-shows-the-snapshot) *Pending edit on version n*,
  [§5.8](../../design.md#58-saving-a-version-history-is-never-changed), and §6.3 `GET`, `PUT` and `DELETE
  {base}/draft` with `baseVersion = n`, and `POST {base}/versions`.
- [note-form.md Routes](../../ux/screens/note-form.md#routes) (`/edit`), States › Kinds of note "Editing a submitted
  note", and Interactions › Edit mode: Save changes and Cancel.
- [note-form.md › Acceptance criteria](../../ux/screens/note-form.md#acceptance-criteria) › Edit mode, discard,
  leaving, session: items 31 and 32. › Validation and Submit: items 30a and 30b. › Common items and groups: item 30i.
- [participant-notes.md › Acceptance criteria](../../ux/screens/participant-notes.md#acceptance-criteria) › Read
  view: item 20 (the Edited line) and item 22 (Edit shown to the author).
- design.md §14 M2 *Done when*: "Each Save changes adds exactly one version, and earlier versions are byte-for-byte
  unchanged." and "A picks change in an edit creates a new version".

Specific to this story:
- [ ] The first change in edit mode creates the editor's pending edit from version n: the same goals, groups
      (including one archived since), items, wording and order, with its ticks, picks, text and flag;
      `PicksCopiedFrom` is `null`.
- [ ] Save changes (`baseVersion = n`) creates version n + 1 with the editor as `CreatedByUserId`, moves
      `CurrentVersionNumber` on in one conditional update, deletes the working copy and writes `note.edited` (version
      numbers, no text), all in one transaction.
- [ ] Byte-for-byte test: after three Save changes, versions 1 and 2 and their group and item rows are exactly as
      first written.
- [ ] A change of picks alone, saved with Save changes, creates a new version whose read view shows the new picked
      groups (automated test).
- [ ] Cancel (`DELETE {base}/draft`) deletes only the caller's pending edit and leaves the submitted note unchanged;
      `404` when there is no pending edit.
- [ ] Until Save changes, everyone else sees the current version; the pending edit is visible only to its editor.
- [ ] The read view, Past notes rows and `GET {base}` (`isEdited`, `lastEdit`) show "Edited" with the last editor and
      time to everyone (A13).
- [ ] Given a worker who is not the author, when they open `/edit` or send `PUT {base}/draft` on a submitted note,
      then they get `403 note.not_editable` and the page "You cannot edit this note" (P).

### Notes

- A note's date and participant can never be changed (§3.8).

As a manager, I want to be stopped and shown the newer version if someone else saved the note while I was editing,
with my changes still on screen,
so that nobody's changes are silently overwritten.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §3.5](../../design.md#35-editing-and-versions) last bullet, §5.8 step 5 (`409 note.version_conflict`),
  §6.3 "When two people edit after submit…" (Start again from the latest version), and §6.7.
- [note-form.md › Acceptance criteria](../../ux/screens/note-form.md#acceptance-criteria) › Conflicts and refusals:
  item 19. note-form.md Components 6 (the version-conflict notice).

Specific to this story:
- [ ] Given version 2 is current and two editors each hold a pending edit on version 2, when both press Save
      changes, then the first creates version 3 and the second gets `409 note.version_conflict` with the newer
      version's number, editor and time; the second keeps their working copy and no version is created for them.
- [ ] Start again sends `PUT {base}/draft` with the new `baseVersion`, which rebuilds the working copy from version 3
      while the editor's picks, ticks, text and flag stay on screen; the next Save changes creates version 4.
- [ ] A retried Save changes with the same `Idempotency-Key` creates no second version.

### Notes
- The notice's heading, body and summary are (P) (note-form.md Q5).
