# F02.07 Version history

**Outcome:** a manager sees every version of a submitted note with who saved it and when, and reads any version in
full, read-only, with the groups picked in that version. Workers never see it (D15, D19, A13,
[design.md §4.5](../../design.md#45-version-history-managers)).

## Stories
- S02.07.01 See a note's versions
- S02.07.02 Read one version in full

## Feature checks
This feature owns these rows in [coverage.md](../coverage.md) (E02):

- [version-history.md › Acceptance criteria](../../ux/screens/version-history.md#acceptance-criteria): Access and
  privacy; Page A; Page B; Not found and errors; Navigation and focus; Layout and display.

Spans its stories and others:

- The axe states and the keyboard and screen-reader passes in Layout and display are run once both stories are done.
- Page A's past-day bullet ("With `isPastDayNote`…") and the past-day line on page B are checked once S02.08.02 is
  done.
- This feature completes the "version history for managers" part of the M2 *Scope* bullet owned by F02.06, and
  participant-notes.md › Read view item 22's Version history link (F02.04).

As a manager, I want to see the list of a note's versions with who saved each one and when,
so that I can see who changed a submitted note and when.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.5](../../design.md#45-version-history-managers): items 1–2 and the state "Not edited since submit";
  §4.4 (the "Version history" link for managers).
- [design.md §6.3](../../design.md#63-today-participants-and-notes): `GET {base}/versions` (managers).
- [version-history.md › Acceptance criteria](../../ux/screens/version-history.md#acceptance-criteria) › Page A: all
  bullets. › Access and privacy: all bullets, for page A. › Not found and errors and › Navigation and focus: the
  bullets about page A. › Layout and display: the page A bullets and states.
- [participant-notes.md › Acceptance criteria](../../ux/screens/participant-notes.md#acceptance-criteria) › Read
  view: items 21 and 22 (the Version history link for managers only).

Specific to this story:
- [ ] `GET {base}/versions` returns `[{versionNumber, createdBy, createdAtUtc, isFlagged}]` to managers; a worker gets
      `403`; another organisation's note and a draft return `404`.
- [ ] `GET {base}` returns `versionCount` to managers only.
- [ ] Opening the version list writes no audit entry (A28).

As a manager, I want to open any version of a note in full, read-only,
so that I can read what a note said before it was corrected and copy old wording into an edit.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.5](../../design.md#45-version-history-managers): item 3 and *Primary action* (no restore), and §3.9
  (earlier versions are the restricted record).
- [design.md §6.3](../../design.md#63-today-participants-and-notes): `GET {base}/versions/{versionNumber}`
  (managers).
- [version-history.md › Acceptance criteria](../../ux/screens/version-history.md#acceptance-criteria) › Page B: all
  bullets. › Access and privacy, › Not found and errors, › Navigation and focus and › Layout and display: the bullets
  about page B.

Specific to this story:
- [ ] `GET {base}/versions/{versionNumber}` returns the version in the read view's `current` shape plus `createdBy`
      and `createdAtUtc`, with common items limited to the Every note group and the groups picked in that version
      (D47). Workers get `403`; a number with no version returns `404`.
- [ ] Opening a version writes no audit entry (A28).
