# F02.04 Past notes and the read view

**Outcome:** anyone can read any submitted note exactly as written and page back through a participant's past notes
(D20). Opening someone else's draft shows a worker only who started it, while a manager can read it and discard it
([design.md §4.4](../../design.md#44-participant-notes-history-and-the-read-view), §4.2).

## Stories
- S02.04.01 Read a submitted note
- S02.04.02 Browse a participant's past notes
- S02.04.03 See someone else's draft, and discard it as a manager

## Feature checks
This feature owns these rows in [coverage.md](../coverage.md) (E02):

- [participant-notes.md › Acceptance criteria](../../ux/screens/participant-notes.md#acceptance-criteria): History
  list; Read view; Both screens.

Delivered by stories in other features or epics (check these parts when those stories are done):

- Read view item 17a (common items: Every note and the picked groups only): S02.05.01, S02.05.02.
- Read view item 20: the Flagged line is built here from `isFlagged` (S02.03.02 makes it reachable); the Edited line
  is S02.06.01; the past-day line is S02.08.02; the To review and Reviewed lines are E03.
- Read view item 22: Edit is S02.06.01; the Version history link is S02.07.01.
- Read view items 24, 25, 26, 28b, 28c and 28d (the manager's review panel) and History list item 10 (To review and
  Reviewed tags) are M3 work in E03, which mentions this feature's rows.
- History list item 11: the Export record link is built by S05.01.01 (record export); Write past-day note by S02.08.01.


As a manager, I want to read a draft that someone else started and discard it when needed, for example one left
unfinished by a worker who has left,
so that the participant's day can be freed for a proper note.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.2](../../design.md#42-today-home-for-everyone) "Someone else's draft", §3.4 (Draft: managers
  read-only), §3.7 (a deactivated user's drafts stay until a manager discards them), §3.8.
- [design.md §6.3](../../design.md#63-today-participants-and-notes): `GET {base}` for a draft (header only; managers
  also get the content, read-only) and `POST {base}/discard`.
- [participant-notes.md › Acceptance criteria](../../ux/screens/participant-notes.md#acceptance-criteria) › Read
  view: items 27 and 28. participant-notes.md States › Read view: "Someone else's draft, worker", "Someone else's
  draft, manager", "Discard dialog".

Specific to this story:
- [ ] Given a draft by Alex P., when a worker calls `GET {base}`, then the response holds only `status`,
      `authorDisplayName` and `startedAtUtc`; a manager also gets the working copy in the `current` shape.
- [ ] A worker sees "Alex P. started today's note for Jane Citizen at 9:14 am. Only Alex P. can finish it." and the
      Past notes link, with no discard control; the API refuses a worker's discard of someone else's draft with
      `403`.
- [ ] Given a manager, when they discard another user's draft, then the note is Discarded with its content kept,
      `note.discarded` records the manager, and the day is free for a new note.
- [ ] A read-only draft never shows the Flagged tag; a ticked flag shows as the read-only "Flag for manager" row with
      its reason.

### Notes
- The earlier-day sentence ("started the note for") and the dialog body lines are (P).
