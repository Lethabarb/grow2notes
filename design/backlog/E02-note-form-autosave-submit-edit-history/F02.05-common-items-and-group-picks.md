# F02.05 Common items and group picks

**Outcome:** the note's Common items section shows the Every note items, asks which other groups happened (starting
from the groups picked on the participant's last submitted note, with a line naming its date) and shows only the
picked groups' items to tick. The picks are saved and versioned with the ticks, and the read view shows Every note and
the picked groups only (D44–D47, [design.md §4.3](../../design.md#43-note-form) item 4,
[§5.7](../../design.md#57-which-items-a-note-shows-the-snapshot)).

## Stories
- S02.05.01 Tick the Every note items
- S02.05.02 Tick which groups happened and their items
- S02.05.03 Start with the last note's group picks
- S02.05.04 Re-check ticks when groups or items change before the first save

When I start a participant's note, I want to find the groups from their last note already ticked, with the date they
came from,
so I can change only what is different today.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §3.1](../../design.md#31-what-a-note-contains) (D46), §3.4 *Group picks*, §4.3 item 4 (the copied line)
  and the state "Group picks copied from the last note" (A47).
- [design.md §5.7](../../design.md#57-which-items-a-note-shows-the-snapshot) *Starting picks*, §5.3
  `NoteDraft.PicksCopiedFrom`, and §6.3 `picksCopiedFrom`.
- [note-form.md › Acceptance criteria](../../ux/screens/note-form.md#acceptance-criteria) › Common items and groups:
  items 30e and 30f.
- design.md §14 M2 *Scope*: "Starting picks copied from the participant's most recent submitted note (D46, A44), with
  the line naming its date (A47)."
- design.md §14 M2 *Done when*: "A new note starts with the last submitted note's picks, skipping archived groups, and
  no item ticks; with no earlier note, nothing is picked."

Specific to this story:
- [ ] The source is the participant's most recent submitted note dated before the note date, by any author, using its
      current version's picks. Archived groups and groups with no active items are left out. Item ticks are never
      copied.
- [ ] `picksCopiedFrom` is the source note's date when at least one pick remains, otherwise `null`. At the first
      `PUT` the server works the source out again and stores it in `NoteDraft.PicksCopiedFrom`; a value sent by the
      client is ignored.
- [ ] Opening a new note with copied picks writes nothing; the first change of any kind creates the draft with the
      copied picks.
- [ ] The copied line never shows in edit mode or on the read view; `PicksCopiedFrom` is always `null` on a pending
      edit and is not copied into versions.

### Notes
- Before Ready: A47 (the copied line) is an assumed default the owner may drop (ux/README Open question 11,
  note-form.md Q13). Dropping it removes `PicksCopiedFrom`, `picksCopiedFrom` and the line; the copying itself (D46)
  stays.
- This is a job story (D46): the situation matters more than the role. Workers and managers alike.

As a worker, I want to be told when a manager changed the common items or their groups while I had the form open,
with my ticks kept where they still apply,
so that my note matches what is set up now.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.3](../../design.md#43-note-form) state "Lists changed before the first save", and
  [§5.7](../../design.md#57-which-items-a-note-shows-the-snapshot) *New draft* (re-apply picks by group ID and ticks
  by item ID).
- [note-form.md › Acceptance criteria](../../ux/screens/note-form.md#acceptance-criteria) › Conflicts and refusals:
  item 17, for groups and items. note-form.md States › Common items and groups: "Lists changed before the first
  save".
- design.md §14 M2 *Done when*: "A goal reworded, or a group renamed, after a draft was created does not change that
  draft or its submitted version." (the group part)

Specific to this story:
- [ ] Given the form is open, when a manager adds, renames, archives or restores a group, or moves an item to another
      group, before the first change, then the first `PUT` returns `409 note.lists_changed` and creates nothing.
- [ ] The reload re-applies picks by group ID (an archived group drops out) and ticks by item ID, keeping ticks only
      for Every note and picked groups (an item moved into an unpicked group loses its tick), keeps the text and shows
      the lists-changed notice.
- [ ] Given a draft created before a manager renamed one of its picked groups, then the draft and its submitted
      version keep the old name (automated test).
