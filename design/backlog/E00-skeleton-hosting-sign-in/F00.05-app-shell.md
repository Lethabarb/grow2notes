# F00.05 App shell

**Outcome:** every signed-in screen sits in the same frame: a skip link, the header with the navigation for the
person's role, generic page titles, one rule for focus and scroll when the screen changes, a session refresh with no
polling, and plain whole-page messages when Grow2Notes cannot start or a page does not exist (design.md §4.0).

## Stories
- S00.05.01 Navigation for my role
- S00.05.02 Keep my place when I move between screens
- S00.05.03 Start-up, refresh and whole-page messages

## Feature checks
Owns these rows in [coverage.md](../coverage.md): `app-shell.md › Structure, privacy and naming`, `app-shell.md ›
Navigation`, `app-shell.md › Refresh`, `app-shell.md › Screen changes, focus and scroll`, `app-shell.md › Start-up and
whole-page messages`.

Other app-shell.md groups: Account and Sign out and Session are F00.04's; Badge is E03's (the To review count arrives
with flag review, design.md §14 M3); Visual and settings is a Definition of Done row.

As a manager, I want the navigation for my role on every screen, so that I can reach Today, Flagged, Report and

### Acceptance criteria
Already specified elsewhere (linked, not copied):

- [app-shell.md](../../ux/screens/app-shell.md) › Acceptance criteria › Navigation, every bullet.
- app-shell.md › Acceptance criteria › Structure, privacy and naming, every bullet (the D42 check itself is built in
  S00.01.05).
- app-shell.md components 1 (skip link), 2 (header), 3 (main region), 3a (before-main bar slot and BackLink
  placement), 5 (Manage page) and 8 (document head).

Specific to this story:
- [ ] `/manage` shows the `<h1>` "Manage" and four links in the design order: Participants, Common items, Guide
      prompts, Users. Until E01 builds them, the first three links open "Page not found".
- [ ] Until E03 and E04 build Flagged and Report, those links open "Page not found". The badge is E03's.
- [ ] Until E02 builds Today, `/` shows Today's heading only, "Today · Thursday 1 October", from `me.today`
      (design.md §4.2 item 1).
- [ ] Both setup paths (S00.04.02, S00.04.03) end on this `/` route (sign-in.md › Setup, "Both setup paths end on
      Today…"), which until now was only S00.01.01's client-route fallback.
- [ ] Page names come from one typed list; a title outside it does not compile.

### Notes
- Not Ready until the owner answers [ux/README.md](../../ux/README.md) open question 1: the `/manage` page, or a Manage
  disclosure in the nav.
- From S00.04.01 (9 October 2026): `GET /api/auth/me` gives `role` as the role's `UserRole` name, `Worker` or `Manager`,
  as the role claim holds it and the policies compare it. Compare `me.role` with `'Manager'`, as the API gives it, not
  with the `'manager'` of app-shell-nav.md's `Header` sketch, which never matches, so a manager would get the worker's
  navigation. For example, type the client's `role` as user-management.md's `Role` (`'Worker' | 'Manager'`), so that the
  sketch's spelling does not compile. The answer has no `toReviewCount` until E03 adds it, for managers only.

As a worker using a screen reader, I want each new screen to put focus on its heading, and Back to return me to the
row I opened, so that I always know where I am.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [ux/README.md](../../ux/README.md) *Global conventions*, rows Focus (the route-change rule) and Back links.
- [app-shell.md](../../ux/screens/app-shell.md) *The route-change rule (one owner)* and component 3a (the shared
  BackLink).
- app-shell.md › Acceptance criteria › Screen changes, focus and scroll, every bullet. In M0 it is checked with Users
  list → user detail → back link; the bullets that name Submit, Discard and Today rows are checked again by E02's
  stories when those exist.

Specific to this story:
- [ ] Scroll positions live in an in-memory map keyed by `location.key`; there is no `<ScrollRestoration>` and nothing
      is written to `sessionStorage`.
- [ ] The success-message store and the arrival-focus flag are in memory only and are empty after a reload.

### Notes
- Planned after S00.06.01, which builds the Users list and the user detail page this story is checked with.
