# F00.02 Azure hosting and deployment

**Outcome:** the test and production environments run in Azure Australia Southeast from Bicep, with no stored
secrets; every merge to `main` reaches test, production deploys are run by hand, telemetry carries IDs only, and
setup links can be emailed.

## Stories
- S00.02.01 Bootstrap Azure for both environments
- S00.02.02 Test environment resources
- S00.02.03 Deploy to test from main
- S00.02.04 Production environment and manual deploy
- S00.02.05 Database delete lock
- S00.02.06 Server telemetry with IDs only
- S00.02.07 Setup-link email

## Feature checks
Owns these rows in [coverage.md](../coverage.md):
- design.md §14 M0 *Scope*, "EF Core and Azure SQL in Australia Southeast, Key Vault, the user-assigned identity, Bicep
  (`bootstrap`, `main`, `locks`) and GitHub Actions deploying to test and prod." (The EF Core context itself is built
  in S00.03.01.)
- design.md §14 M0 *Scope*, "Telemetry in Australia Southeast that never records request bodies or SQL error text."
- design.md §14 M0 *Done when*, "Deleting the test SQL server is refused while its database is locked (or the fallback
  in §10.1 is recorded)."

Backups beyond the platform defaults (35-day point-in-time restore, monthly long-term retention, the restore test)
and the uptime and error alerts are E06's (design.md §14 M6 *Scope*, Backups and Monitoring).
