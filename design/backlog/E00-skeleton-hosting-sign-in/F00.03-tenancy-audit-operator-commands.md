# F00.03 Tenancy, audit and operator commands

**Outcome:** every tenant-owned row belongs to one organisation, and the model, the database and the tests keep it
there (D3); every state change can write its audit entry in the same transaction (A28); requests are denied by
default; and the operator can create the organisation with its first manager, and break glass when needed.

## Stories
- S00.03.01 Database context, conventions and first migration
- S00.03.02 Tenant isolation and its tests
- S00.03.03 Audit writer
- S00.03.04 Deny by default, CSRF and the endpoint matrix
- S00.03.05 Bootstrap the organisation and first manager
- S00.03.06 Break-glass reset and sign-out of everyone

## Feature checks
Owns these rows in [coverage.md](../coverage.md):
- design.md §14 M0 *Scope*, "The Organisation table, `OrganisationId` on every `ITenantOwned` entity with the named
  query filter, and the `grow2notes_runtime` database role (D3)."
- design.md §14 M0 *Scope*, "The audit table, starting with sign-in and user events. The operator commands." (The
  sign-in events are written by F00.04's stories and the user events by F00.06's; this feature builds the table and
  the writer.)
- design.md §14 M0 *Done when*, "A test fails the build if any `ITenantOwned` entity lacks the organisation filter; the
  named exceptions (`AspNetUsers`, Identity child tables, `DataProtectionKeys`) are listed in the test."

Enabler: the fallback policy that requires role Worker or Manager by name, the `Manager` policy, antiforgery (`GET
/api/auth/antiforgery` and the `X-XSRF-TOKEN` check on the `/api` group), JSON-only request bodies, the `If-Match`
helper (`428 precondition.required`, `412 precondition.failed`), problem+json errors with the design.md §6.9 codes,
and the table-driven endpoint matrix test. So that a new endpoint without a matrix row fails the build, and every
later story's permission and organisation-scoping tests come almost for free.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- design.md §2 *How it is enforced*; §9.1; §9.8 items 1 to 3; §6.1 Errors.
- mcp-server.md §3.5 convention 4 (roles are named, never inferred).

Specific to this story:
- [ ] The matrix calls every endpoint from `EndpointDataSource` as anonymous, worker, manager and a manager of the
      second organisation, and asserts the expected `401`, `403`, `404` or `2xx`; an endpoint with no row fails the run.
- [ ] Given a signed-in user whose role value is neither Worker nor Manager (a test-only value), when they call any
      endpoint behind the fallback policy, then `403`.
- [ ] A `POST`, `PUT` or `DELETE` without a valid `X-XSRF-TOKEN` is refused, and a form-encoded body is refused.
- [ ] The `If-Match` helper returns `428` when the header is missing and `412` when it is stale (unit tests).

### Notes
- From S00.01.01: when the fallback policy lands, mark the index.html fallback (`MapFallbackToFile`), the static
  assets (`MapStaticAssets`), the unknown-`/api` catch-all and both health endpoints `AllowAnonymous`, so a signed-out
  user still gets the sign-in page and an unknown `/api` path stays `404` (not `401`), and App Service's health probe
  (no credentials) still gets `/healthz`. Cover each with a row in the endpoint matrix.
- From S00.01.01: an unhandled exception in Production currently gives Kestrel's bare empty `500`; the problem+json
  handler (`UseExceptionHandler` + `AddProblemDetails`) fixes that, and its `/api` responses keep `no-store` through
  `CacheHeaders` (checked in a scratch app).
