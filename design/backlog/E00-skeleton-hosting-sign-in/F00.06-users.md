# F00.06 Users

**Outcome:** managers control who can sign in and in which role: they invite people, resend invites, change a name,
email or role, reset a sign-in, and deactivate or reactivate an account, with the last-manager and one-email rules
held by the server (D23, D24, A26, A27). Users are never deleted.

## Stories
- S00.06.01 See who can sign in
- S00.06.02 Invite a user
- S00.06.03 Resend an invite
- S00.06.04 Reset someone's sign-in
- S00.06.05 Deactivate and reactivate a user
- S00.06.06 Change a user's name, email or role

## Feature checks
Owns these rows in [coverage.md](../coverage.md):
- design.md §14 M0 *Scope*, "Manager screen: invite, edit, reset sign-in, deactivate and reactivate users."
- design.md §14 M0 *Done when*, "After deactivation, the user's next request is rejected (tested)."
- `users.md › Access`, `users.md › List`, `users.md › Invite`, `users.md › Detail and actions`, `users.md › Edit`.

`users.md › General` is a Definition of Done row.

As a manager, I want to resend an invite whose link has expired, so that the person can still set up their account.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- design.md §4.11 *Resend invite*; §6.6 `POST /api/admin/users/{id}/setup-link` (Invited).
- [users.md](../../ux/screens/users.md) › Acceptance criteria › Detail and actions, AC23 and AC33.

Specific to this story:
- [ ] The new link replaces the old one: the old link now returns `410 auth.setup_link_invalid`.
- [ ] `user.setup_link_sent` is written; a stale `If-Match` returns `412` and sends nothing.

### Notes
- From S00.03.04 (PR #26 review, 9 October 2026): the first user change with `If-Match`; S00.06.04 to S00.06.06 do
  the same. Write the user's `ETag` header with `IfMatch.ETag`, given their `ConcurrencyStamp`; load the user filtered
  by the caller's organisation, so another organisation's is `404` first (users have no query filter, and A48's token
  is only on `ITenantOwned` rows: design.md §5.9 item 5), then call `IfMatch.Check` with the stamp before saving, and
  answer the problem it returns, if any. A save that finds the user changed since loading answers
  `ErrorCode.PreconditionFailed.Problem()`, never `500`: a save through the context throws
  `DbUpdateConcurrencyException`, which the endpoint catches, and `UserManager`'s store catches it itself and returns
  an `IdentityResult` with the `ConcurrencyFailure` error. Add the endpoint's matrix row.

As a manager, I want to reset the sign-in of someone who lost their phone or forgot their password, after checking who
is asking, so that they can set up again from a new link.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- design.md §4.11 *Reset sign-in*; §8.6 *Reset sign-in* and *Last active manager*; §4.13 *Lost phone*.
- [users.md](../../ux/screens/users.md) › Acceptance criteria › Detail and actions: AC22, AC24, AC25, AC29 (reset

Specific to this story:
- [ ] In one transaction the password, passkeys and TOTP are removed, a new authenticator key is generated (rotating
      the stamp), Status becomes Invited and `user.setup_link_sent` is written; then the new link is emailed.
- [ ] Given the person is signed in on two devices, when the reset completes, then both sessions get `401` on their
      next request.
- [ ] Given the caller is the only active manager, when they reset themselves, then `409 user.last_manager` and
      nothing changes (A26).
- [ ] After a reset the person completes either setup path again (S00.04.02, S00.04.03).

### Notes

  question 6; users.md open question 1).

- [ ] Given the caller is the only active manager, when they deactivate themselves, then `409 user.last_manager`.
- [ ] Reactivate sets Status Active, ends the lockout and writes `user.reactivated`; the person signs in with their
