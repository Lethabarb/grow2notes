# F00.01 Skeleton and continuous integration

**Outcome:** one ASP.NET Core 10 app serves the React SPA and the API from the same origin, every pull request is
built and tested in CI, and the shared building blocks that every screen uses (tokens, buttons, loading and error
handling, the copy module and its checks) exist once.

## Stories
- S00.01.01 Serve the SPA and the API from one origin
- S00.01.02 Build and test every pull request
- S00.01.03 Shared look, buttons and page status
- S00.01.04 Shared loading, failure and form-error handling
- S00.01.05 Copy module, date formats and wording checks

## Feature checks
Owns this row in [coverage.md](../coverage.md): design.md §14 M0 *Scope*, "ASP.NET Core on .NET 10 LTS serving the
React (Vite, TypeScript) build from the same origin; unknown `/api` paths return 404."

The building blocks in S00.01.03–S00.01.05 own no coverage row of their own. They are the first build of mechanisms
that the Definition of Done ([README §9](../README.md#9-definition-of-done)) checks on every story.

Enabler: one .NET 10 solution in the design.md §7.3 layout, whose single web app serves the Vite-built React SPA and
the `/api` routes from the same origin, with the two health endpoints and the Melbourne clock. So that every later
story has one deployable to land in, with one cookie origin, no CORS and no second hosting service.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §14 M0](../../design.md#m0-skeleton-hosting-sign-in) *Scope*, bullet 1.
- design.md §7.2, every bullet (same origin, no login redirects, caching, strict-CSP build settings, development proxy,

- [app-shell.md](../../ux/screens/app-shell.md) component 8, Document head. (Its checks sit in `app-shell.md ›
  Structure, privacy and naming`, owned by F00.05.)

Specific to this story:
- [ ] `GET`, `POST`, `PUT` and `DELETE` on an unknown `/api/...` path each return `404`, never `index.html`; an unknown
      client route such as `/manage/anything` returns `index.html` (integration test).
- [ ] Hashed assets carry `Cache-Control: public, max-age=31536000, immutable`, `index.html` carries `no-cache`, and
      every `/api` response carries `no-store` (integration test).
- [ ] The production build has `build.assetsInlineLimit: 0` and its `index.html` contains no inline script.
- [ ] `/healthz` answers `200` without opening a database connection; `/healthz/ready` fails when the database is
      unreachable (integration test with the SQL container stopped).
- [ ] `TimeProvider` is registered and `MelbourneClock.Today()` gives the Australia/Melbourne date for a
      `FakeTimeProvider` instant (unit test).
- [ ] `global.json` pins the .NET 10 SDK, package versions are central in `Directory.Packages.props`, and the solution
      is `Grow2Notes.slnx`.

### Notes
- This story builds the one Melbourne clock, `MelbourneClock`, that every later story uses: `/api/auth/me`

  settable clock in the integration test host are S02.02.01's.
- Sprint 01 planning: this story is merged before `ci.yml` exists. It counts as done once S00.01.02's first run on
  `main` is green, and S00.02.03's first deploy (Sprint 02) checks it in test (releases.md, assumption 5).

Enabler: `ci.yml`, running design.md §10.4 steps 1 to 5 on every pull request and every push to `main`. So that each
story's "CI is green" check in the Definition of Done is automatic, and production deploys exactly the artifacts that
passed.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- design.md §10.4 `ci.yml`, steps 1 to 5.
- [README §9](../README.md#9-definition-of-done), "CI is green".

Specific to this story:
- [ ] `main` accepts changes only through a pull request with this workflow passing (the Definition of Done's "Merged"
      and "CI is green" lines).
- [ ] A build warning, a failing test, a NuGet Audit high or critical advisory, an `npm audit --omit=dev
      --audit-level=high` finding, a type error, a lint error or a model change without a migration each fail the run
      (try each once on a throwaway branch).
- [ ] Integration tests run against SQL Server in Testcontainers; Playwright smoke tests with axe run against the
      published app on a SQL Server container.
- [ ] The run uploads `app.zip`, the self-contained `linux-x64` `efbundle`, the idempotent `migrate.sql` and the built
      Bicep as artifacts.
- [ ] Every third-party Action is pinned to a commit SHA (design.md §9.11).

### Notes
- The NuGet and npm audits and the SHA pinning are built and proven here, because the Definition of Done needs them
  from the first story. Only Dependabot is left to E06 (S06.01.03; design.md §14 M6 *Scope*, "dependency scanning").
- Sprint 01 planning: planned after S00.01.01 and S00.03.01, because the `efbundle`, `migrate.sql` and
  pending-model-changes steps need the first migration.
- Sprint 01 planning: there are no Bicep files until Sprint 02 (S00.02.01, S00.02.02). The `az bicep build` step is
  written now and builds whatever `infra/` holds; S00.02.03's first deploy uses its artifact, which checks that part of
  the artifacts criterion (releases.md, assumption 5).
- Open owner question, needed at Sprint 01 planning: is the repository public or private, and if private, is GitHub
  Pro taken? On a private repository, GitHub Free cannot enforce the first criterion; design.md §10.2 budgets GitHub
  Pro only for a private repository (releases.md, owner questions and assumption 6).

### Tasks
- [ ] Add the SPA's ESLint, type-check and Vitest set-up so CI has each step to run
- [ ] Write the `ci.yml` .NET steps: restore with NuGet Audit (high and critical fail the build), build with warnings as
      errors, `dotnet test`, `dotnet ef migrations has-pending-model-changes`
- [ ] Write the SPA steps: `npm ci`, `npm audit --omit=dev --audit-level=high`, type-check, lint, Vitest and
      `vite build`
- [ ] Write the package steps: `app.zip`, the self-contained `linux-x64` `efbundle`, the idempotent `migrate.sql`, and
      `az bicep build` over `infra/`
- [ ] Add the first Playwright smoke test with axe, run against the published app on a SQL Server container
- [ ] Upload the artifacts, and pin every third-party Action to a commit SHA
- [ ] Protect `main`: changes only through a pull request with this workflow passing
- [ ] Prove each failure once on a throwaway branch (a warning, a failing test, a NuGet advisory, an npm finding, a type
      error, a lint error, a model change without a migration), then delete the branch


Enabler: the `api()` wrapper (problem+json with its stable `code`, the 10-second timeout, the `X-XSRF-TOKEN` header,
the `401` hand-off), the TanStack Query client with memory-only cache, the load region (nothing for 1 second, then
"Loading [things]…", then the failure sentence with Try again), the error summary with inline field errors, and the
request-failure alert above a pressed button. So that every screen loads, fails and reports errors the same way, and
nothing reaches device storage (D22).

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [ux/README.md](../../ux/README.md) *Global conventions*, rows Messages and Device and data.
- [empty-loading-error.md](../../ux/components/empty-loading-error.md) and
  [form-validation.md](../../ux/components/form-validation.md) recommendations.

Specific to this story:
- [ ] The query client has no persister; `refetchOnWindowFocus` is off by default; queries retry once, silently, on
      a network failure, a timeout or a `5xx`; mutations never retry.
- [ ] A load that fails shows "[Thing] did not load: no connection. Try again."; a failed Try again shows "[Thing]
      still did not load: no connection. Try again." (Vitest with fake timers).
- [ ] The error summary is first in `<main>`, above the `<h1>`, takes focus on a failed submit, and its links focus
      their field without changing the URL; the page title gains "Error: ".
- [ ] Every `POST`, `PUT` and `DELETE` sends `X-XSRF-TOKEN` from memory (design.md §9.8).
- [ ] A `401` from any call except `/api/auth/login*`, `/api/auth/setup/*` and `/api/auth/logout` raises the
      session-ended event that S00.04.08 listens for.
