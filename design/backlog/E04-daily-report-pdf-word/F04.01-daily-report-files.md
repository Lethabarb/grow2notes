# F04.01 Daily report files

**Outcome:** a manager downloads one day's submitted notes as a Word (.docx) or PDF file. One shared report model
feeds both renderers, so the two files hold the same content in the same order: each note's current version exactly as
written, with its markers, and no counts or drafts. Each file is built fresh in memory, streamed to the browser and
audited ([design.md §11](../../design.md#111-what-the-report-is), [§6.5](../../design.md#65-reports-and-exports-managers-d26d30-d43)).

## Stories
- S04.01.01 Download a day's notes as a Word file
- S04.01.02 Download the day's notes as a PDF
- S04.01.03 Show common items by picked group
- S04.01.04 Show each note's markers
- S04.01.05 Mark every page as confidential
- S04.01.06 Download a full day in under 10 seconds

## Feature checks
Rows owned, in [coverage.md](../coverage.md) under E04:
- design.md §14 M4 Scope: "everything in §11.1–11.5: the shared report model", "the PDFsharp-MigraDoc renderer",
  "the Open XML SDK renderer" and "audit entries for report downloads".
- design.md §14 M4 Done when: every bullet except "Workers get `403`" (owned by F04.02).

Spanning the stories:
- [ ] One text-match fixture day holds every case at once: an edited note; flagged notes that are To review,
      Reviewed with a comment, and flag removed later; a past-day note; a note submitted the next day; an archived
      participant; a note with no goals; a note with only Every note; a note with no common items; an unpicked group;
      and a draft and a discarded draft for the same day. The Word text and the PDF text both match the stored notes
      (M4 Done when bullet 1), and the draft and discarded draft appear in neither.

As a manager, I want to download one day's submitted notes as a single Word file,
so that I can read, spot-check and file the day's notes as one document.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §6.5](../../design.md#65-reports-and-exports-managers-d26d30-d43), the export row with `format=docx`:
  managers only, every submitted note with that note date as its current version, family then given name, the
  `Content-Disposition` file name, and `404 report.no_notes` for a day with no submitted notes, including any future
  date.
- [design.md §11.1–11.3](../../design.md#111-what-the-report-is): the title block (organisation name, "Daily progress
  notes", the date, "As at", "Exported by") and, for each note, the participant, Written by, Submitted, Goals ("No
  goals set" when none) and Guided notes with line breaks kept.
- [design.md §11.5](../../design.md#115-pdf-and-word-layout), Word column: A4 portrait, 20 mm margins, Arial 11 pt,
  Title and Subtitle styles, Heading 1 per participant, Heading 2 per section, ☑ and ☐ as text in Segoe UI Symbol,
  the file name.
- [design.md §14 M4](../../design.md#m4-daily-report-pdf-and-word) Done when: "No drafts and no counts appear…"
  (Word), "A day with no submitted notes, including a future date, returns `404 report.no_notes` and no file", and
  "the Word file opens in desktop and mobile Word, with participant headings in the desktop Navigation pane".
- [daily-report.md › Acceptance criteria › Downloads](../../ux/screens/daily-report.md#acceptance-criteria), bullets
  "Download Word saves…" (the Word half), "No part of the report, no preview…" and "The object URL is revoked within
  60 s…".

Specific to this story:
- [ ] Given a manager, when they download Word for a day with notes, then one `report.downloaded` audit entry with
      the date and format `docx` is written before the response is sent (§5.3 AuditEvent).
- [ ] Given a worker, when they call `GET /api/reports/daily/{date}/export?format=docx`, then the response is `403`
      and no audit entry is written. Given a manager of a second organisation, then a day with notes only in the
      first organisation returns `404 report.no_notes`.
- [ ] A participant archived since still appears when they have a submitted note for that day (§11.3).
- [ ] An automated test reads the Word file's text and finds, for each note, the name, author, submitted time, every
      goal with its tick, and the Guided notes text exactly as stored, and finds no draft or discarded draft.
- [ ] The file is built in memory and streamed; nothing is written to server disk or storage (A19, §7.1).
- [ ] The parent company name check from S00.01.05 also runs over a generated Word file's text and properties (D42).
- [ ] A first Report screen at `/reports/daily/{date}` shows the `<h1>` "Daily report" and **Download Word** for the
      URL date, saving through the file-download mechanism in [file-download.md](../../ux/components/file-download.md)
      (fetch, `blob:` URL, temporary `<a download>`); F04.02 completes the screen.
- [ ] Named manual check in test: the file opens in desktop Word on Windows and in mobile Word on a phone, and each
      participant is a heading in the desktop Navigation pane. Record the result in Notes.

### Notes
- Common items (S04.01.03), the markers (S04.01.04) and the running header, footer and metadata (S04.01.05) are
  added to the same model and to both renderers later.
- E05's participant record export lays out its notes "like the daily-report block" (§11.6); nothing extra is built
  for it here.
- The 10-a-minute export limit (§9.9) is built with M6's rate limiting (E06).

As a manager, I want the same day's notes as a PDF,
so that I can print or file a copy that looks the same on every device.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §11.5](../../design.md#115-pdf-and-word-layout), PDF column: A4 portrait, 20 mm margins, DejaVu Sans
  11 pt embedded, the title block, the participant name as a heading kept with the lines below it, a thin rule between
  notes, no forced page breaks, ☑ and ☐ as text, the file name.
- [design.md §7.5](../../design.md#75-key-libraries), the PDF row: PDFsharp-MigraDoc 6.2 with a small font resolver
  for the static TrueType font.
- [design.md §14 M4](../../design.md#m4-daily-report-pdf-and-word) Done when: "An automated test confirms the PDF
  text and the Word text both match the stored notes", "Every character in a rendered PDF exists in the embedded
  font, including ☐ and ☑", "No drafts and no counts appear…" (PDF) and "The PDF opens in Edge and Acrobat".
- [daily-report.md › Acceptance criteria › Downloads](../../ux/screens/daily-report.md#acceptance-criteria), bullet
  "Download Word saves… Download PDF saves…" (the PDF half).

Specific to this story:
- [ ] `format=pdf` is rendered from the same `DailyReportModel` as `format=docx`; the text-match test compares both
      files with the stored notes for the same fixture day.
- [ ] Given a worker, when they call `…/export?format=pdf`, then the response is `403`; each manager PDF download
      writes one `report.downloaded` entry with format `pdf`.
- [ ] The font test's fixture holds ☐, ☑ and the characters staff type in Australian English on phones and laptops:
      curly quotes and apostrophes, en and em dashes, and accented letters in names (see Notes).
- [ ] The DejaVu Sans font file and its licence text are in the repository, and the renderer loads no other font at
      run time (Linux App Service has no Windows fonts, §7.5).
- [ ] **Download PDF** on the Report screen saves `daily-notes_{date}.pdf`.
- [ ] The parent company name check from S00.01.05 also runs over a generated PDF's text and document information
      (D42).
- [ ] Named manual check in test: the file opens in Edge and in Acrobat Reader. Record the result in Notes.

### Notes
- What the PDF should show for a character DejaVu Sans lacks (for example an emoji typed on a phone keyboard) is an
  open question for the owner; §11.5 sets only the test. This story is not Ready until it is answered.

Already specified elsewhere (linked, not copied):
- D47; A4; [design.md §11.3](../../design.md#113-layout), the Common items row;

      reads "No common items set".
- [ ] A group not picked on the version leaves no trace in either file, including its items' wording.
- [ ] In Word, each group name is a Heading 3 under the Common items Heading 2.
- [ ] The text-match fixture covers Every note only, two of three groups picked, and no common items, in both files.

As a manager, I want the file to show which notes were edited, flagged, reviewed, written as past-day notes or
submitted on a later day,
so that I read each note in its full context when I spot-check the day (D17, A16).

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §11.3](../../design.md#113-layout), the rows Written by (past-day, A11), Submitted (later day), Flag and
  Edited, with the wording in the layout example; A18 (the current version, with an Edited marker).
- [design.md §14 M4](../../design.md#m4-daily-report-pdf-and-word) Done when: "Edited, flagged, reviewed,
  submitted-next-day and past-day notes each show the right marker".
- [design.md §14 M3](../../design.md#m3-flag-review) Done when bullet 2, the part "in the report" ("Reviewed by … on
  …"), owned by F03.03 and checked here.

Specific to this story:
- [ ] The flag line takes its reason from the version in `FlaggedVersionNumber`, adds "(flag removed in a later
      edit)" when the current version is not flagged, then shows "To review", or "Reviewed by {name}, {time}" with the
      latest review's comment.
- [ ] A note that was never submitted with a flag has no flag line, even if a draft had the flag ticked.
- [ ] "Edited · N versions · last change by {name}, {time}" appears only when there is more than one version.
- [ ] Times are Melbourne time (A33), with the date added when a time falls on a later day than the note date
      (§11.3).
- [ ] Each marker case is in the text-match fixture, in both files.

### Notes
- Reads `Note.FlagStatus`, `FlaggedVersionNumber` and `NoteReview` from E03 (S03.01.01, S03.02.01).
