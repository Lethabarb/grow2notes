# F04.01 Daily report files

**Outcome:** a manager downloads one day's submitted notes as a Word (.docx) or PDF file. One shared report model
feeds both renderers, so the two files hold the same content in the same order: each note's current version exactly as
written, with its markers, and no counts or drafts. Each file is built fresh in memory, streamed to the browser and
audited ([design.md §11](../../design.md#111-what-the-report-is), [§6.5](../../design.md#65-reports-and-exports-managers-d26d30-d43)).

## Stories
- S04.01.01 Download a day's notes as a Word file
- S04.01.02 Download the day's notes as a PDF
- S04.01.03 Show common items by picked group
- S04.01.04 Show each note's markers
- S04.01.05 Mark every page as confidential
- S04.01.06 Download a full day in under 10 seconds
- S04.01.07 The daily report reads like the Word document
- S04.01.08 Name the report by weekday and date
- S04.01.09 Record the Word-template decision, defaults and set-up list

## Feature checks
Rows owned, in [coverage.md](../coverage.md) under E04:
- design.md §14 M4 Scope: "everything in §11.1–11.5: the shared report model", "the PDFsharp-MigraDoc renderer",
  "the Open XML SDK renderer" and "audit entries for report downloads".
- design.md §14 M4 Done when: every bullet except "Workers get `403`" (owned by F04.02).

Spanning the stories:
- [x] One text-match fixture day holds every case at once: an edited note; flagged notes that are To review,
      Reviewed with a comment, and flag removed later; a past-day note; a note submitted the next day; an archived
      participant; a note with no goals; a note with only Every note; a note with no common items; an unpicked group;
      and a draft and a discarded draft for the same day. The Word text and the PDF text both match the stored notes
      (M4 Done when bullet 1), and the draft and discarded draft appear in neither. (T20:
      `DailyReportTextMatchTests`.)
