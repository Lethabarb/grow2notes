# F04.02 Report screen

**Outcome:** on the Report screen a manager reaches any day up to today, by stepping a day at a time or by typing or
picking a date, sees plainly when a day has no submitted notes, and knows whether each download worked. The screen
shows no part of the report, no count and no preview (D43, D26,
[design.md §4.7](../../design.md#47-daily-report-managers)).

## Stories
- S04.02.01 Move a day at a time
- S04.02.02 Pick a date in the date field
- S04.02.03 See when a day has no submitted notes
- S04.02.04 Know whether a download worked
- S04.02.05 Save the report on a phone

## Feature checks
Rows owned, in [coverage.md](../coverage.md) under E04:
- design.md §14 M4 Scope: "the Report screen (4.7)".
- design.md §14 M4 Done when: "Workers get `403`".
- [daily-report.md › Acceptance criteria](../../ux/screens/daily-report.md#acceptance-criteria): Routing and access,
  Date field and stepping, Has-notes and the empty day, Downloads, and Real devices, test environment with the
  production CSP (M4).

daily-report.md › Copy and layout is marked DoD and is checked on every story here.

Spanning the stories:
- [ ] The endpoint matrix test has rows for `GET /api/reports/daily/{date}/has-notes` and
      `GET /api/reports/daily/{date}/export` in both formats: anonymous `401`, worker `403`, manager `2xx` or
      `404 report.no_notes`, and a manager of a second organisation never sees the first organisation's notes.

### Acceptance criteria
Already specified elsewhere (linked, not copied):
- [design.md §4.7](../../design.md#47-daily-report-managers) *States*; [§6.5](../../design.md#65-reports-and-exports-managers-d26d30-d43),

- [ ] Given a worker, when they call `GET /api/reports/daily/{date}/has-notes`, then the response is `403`.
- [ ] `hasNotes` is true only when the date has at least one Submitted note; a draft or a discarded draft alone gives
      false, and so does any future date.
- [ ] The response holds only `date` and `hasNotes`: no count and no note content (D26).
